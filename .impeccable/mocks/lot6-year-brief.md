# Annual archive and purge — design brief

Mode: Operate. New teacher workflow in the existing luma workspace, entered from Classes. No global identity, sidebar or theme redesign. The approved business plan already defines year-scoped deletion and durable modules.

- Job: close an old teaching year, optionally archive without deleting, then deliberately remove that year's classes and student data. Show the exact selected year, classes, student and private-record counts. Distinguish preserved module data visually from removed annual data.
- Before purge: link to every module/class final PDF. Do not claim to know which files the teacher downloaded. Explicitly acknowledge keeping necessary PDFs; incomplete or unavailable exports are reported, without inventing a requirement that every teaching context must have graded results. PDF-only archives cannot restore criterion details.
- Archive: keep the operation reversible before purge, with explicit reopening to resolve outstanding work if needed. Remove yearly contexts from active preparation/grading, preserve classes/student records until purge, and allow read-only inspection and eligible PDF exports while those records exist. The current final-export service rejects archived contexts: supporting retained archived records is an implementation adjustment to resolve explicitly, not behavior already delivered. Keep draft publication restrictions and retained public module snapshots.
- Purge: delete annual classes, student identities, corrections/points/submissions/history, private semester comments, correction proposals and their decision records. Keep teacher/passkeys/agent access, modules/preparation/objectives/source references/selected links/rubrics, retained context class/year labels, lessons/calendars/deadlines and valid publication snapshots. Archive remaining yearly contexts before deleting classes atomically. Public module links remain; deleted class directories disappear. No Drive file operation or local file deletion.
- Interaction: ordinary archive action is separate from the irreversible purge. Preparing purge opens a protected final confirmation with the selected year/counts, a necessary-PDF acknowledgement and a year field. It uses the incumbent shadcn AlertDialog/Form/Formsnap/Superforms/Zod conventions; no extra account or backup flow. Revalidate the reviewed scope/revisions transactionally; HTTP 409 requires explicit refresh and another confirmation. Retry must not repeat a successful destructive operation. Never purge actual data as part of implementation checks.
- States: choose year rather than default to the current active year; empty/no classes, archive available/already archived, PDF ready/incomplete, preview loading, conflict/error, mutation pending and completion. After purge show retained module context history without implying student data remains. Keep long names wrapping, 44px controls, keyboard focus, readable alerts and responsive stacking.

Fictional shared preview: year 2025-2026; B2 Demo and B3 Demo, twelve students each; three teaching contexts across Application web and Conception back-end; 72 corrections, 24 private comments and four agent proposals. Three complete PDF grids are eligible, never marked already downloaded. Three calendars remain with two reusable modules; two public module pages remain. No student names are needed in the annual recap.
